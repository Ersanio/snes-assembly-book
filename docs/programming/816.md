# 8-bitモードと16-bitモード
スーパーファミコンは、8-bitモードと16-bitモードの両方に対応しています。
すなわち、アキュムレータ、Xレジスタ、Yレジスタは8-bit値ではなく16-bit値を保持します。

以下で紹介するいくつかの方法で、8-bitモードと16-bitモードを切り替えることができます。

|命令|説明|
|-|-|
|REP #$10|XレジスタとYレジスタを16-bitモードにする|
|REP #$20|アキュムレータを16-bitモードにする|
|REP #$30|アキュムレータ・Xレジスタ・Yレジスタを16-bitモードにする|
|SEP #$10|XレジスタとYレジスタを8-bitモードにする|
|SEP #$20|アキュムレータを8-bitにする|
|SEP #$30|アキュムレータ・Xレジスタ・Yレジスタを8-bitモードにする|

オペコードREPとSEPについては本書の後半で解説しますが、現在のところは以上の内容を理解するだけで十分です。

また、アキュムレータが16-bitモードのとき、以下の機能が有効になります。

* メモリにアクセスする場合、2つのRAMアドレスを1つのアドレスとして取り扱える
* これら2つのRAMアドレスは常に隣り合ったアドレスである
* 即値(#$)は16-bitを取る
* 数値のロードとストアがリトルエンディアンで行われる。しかし、このことについて考慮する必要はない

さっそく例を見てみます。

```
REP #$20
LDA #$0001
STA $7E0000
SEP #$20
```
命令を1つずつ見ていきます。

```
REP #$20
```
この命令は、アキュムレータを16-bitモードに設定します。

```
LDA #$0001
```
この命令はアキュムレータに16-bit値$0001をロードします。
よって、アキュムレータは$0001を保持します。

{% hint style="info" %}
もしLDAのオペランドに$0001ではなく$01と記述した場合、コードはほとんどの場合クラッシュするでしょう。
なぜなら、オペコードはオペランドに16-bit値が取られることを予期しているにも関わらず、オペランドに8-bit値しか与えられなかったからです。
その結果、その後に続くオペコードが期待通りに動作しなくなってしまいます。

オペランドに関わらず、それぞれのオペコードはアセンブル時に8-bit値へ変換されます。
これがROMファイルをHex Editorで開くと16進数値しか現れない理由です。
これらの数値を人間が読むことのできるアセンブリ言語にディスアセンブルするには、「ディスアセンブラ」を用いる必要があります。
{% endhint %}

```
STA $7E0000
```
この命令は、16-bit幅のアキュムレータが保持している値をRAMアドレス$7E0000**と**$7E0001にストアします。
なぜ2つのアドレスなのでしょうか。
なぜなら、16-bit値は1つのアドレスに収まりきらないからです。
前述した通り、1つのアドレスは8-bit幅しか持たないため、2つのアドレスを用いることで16-bit値を表現できるのです。
この場合、$7E0000と$7E0001は結合されて、数値$0001を保持します。

```
SEP #$20
```
この命令は、アキュムレータの16-bitモードを終了します。

これら4つの命令を実行した後のRAMの状態を考えると、以下のようになります。
```
$7E0000 | [01] [00] [XX] [XX] [XX] […]
```
最初の数値は$01で、これはRAMアドレス$7E0000に保持されています。
次の数値は$7E0001に保持されており、3つ目の数値は$7E0002に保持されています。

以上から分かるように、ストアされた数値はリトルエンディアン形式になります。
しかし、通常このことについて考慮する必要はありません。
また、この領域から再度アキュムレータに数値をロードしようとする場合は、単純に`LDA $7E0000`を実行するだけです。
アキュムレータが16-bitモードであれば、この命令は、アキュムレータに再び数値$0001をロードします。
もしアキュムレータが8-bitモードであれば、アキュムレータには$01がロードされます。

なお、XレジスタとYレジスタの16-bitモードも存在します。
これらの16-bitモードはアキュムレータの16-bitモードとは独立しており、
もしアキュムレータが8-bitモードでXレジスタとYレジスタが16-bitモードなら、以下のようなコードが実行可能です。

```
LDA #$13
LDX #$4242
```
